# Breadcrumb 产品设计草案 v0.1

> 状态：待 Leo 审核。
> 名字的寓意：学习路上撒下的面包屑——回头看，能看见自己真实走过的路（成就感）；
> 向前看，不会在森林里迷路（知识树与方向感）。

## 一句话定位

**本地优先的 AI 学习伴侣：让学习被看见、被记住、不焦虑。**

市面上的学习工具在让人"更自律"，Breadcrumb 反过来：不施压，只反馈。
它相信成就感和自我觉察比打卡和督促更能产生持续的学习动力。

## 目标用户

看重反馈与自我觉察、希望获得无压力高动力学习体验的学习者：

1. **用 AI 自学的人**——每天和 AI 对话学习，但对话是线性的，学了什么、学到哪了、忘了多少，全都看不见。
2. **备考者**——需要知道"考试那天我大概还记得多少"，而不是焦虑地重复刷题。
3. **容易学习焦虑的人**——凌晨两点还在追问 AI"为什么还是报错"，需要的不是更多知识，而是被看见和被善待。

## 五条产品原则（所有设计决策的最高裁判）

1. **减压是第一功能。** 一切反馈用"你已完成"的语言，永不使用"你落后了"的语言。没有连续打卡中断提醒，没有红色警告。
2. **用户拥有一切。** 数据全部本地存储（SQLite 单文件），断网可用核心功能，联网功能有总开关，任何数据不经用户同意不出本机。
3. **一切可开关、可计价。** 每个消耗 token 的环节有独立开关和独立计价器，外加不可关环节合计器与总计器。用户永远知道钱花在哪。
4. **插件即产品。** 官方功能自己也是插件，与社区开发者平权。开发者体验与用户体验并列第一。
5. **温柔的智能。** 心理监测默认关闭、首次使用明确征求同意；它只说"要不要休息一下"，永不说"你状态很差"。

## 功能地图

### 核心壳（不可拆卸的最小主体）

| 模块 | 说明 |
|------|------|
| **对话学习** | 与 AI 对话的主界面，产品心脏。所有其他功能都寄生在对话产生的数据上——这是 Breadcrumb 最重要的设计洞察：**对话即数据，无需用户额外付出任何记录成本** |
| **数据层** | 本地 SQLite；对话、知识节点、行为事件统一建模；插件按命名空间隔离读写 |
| **模型管理** | API 配置（各环节可独立配置）、本地模型（Ollama 集成 + 硬件检测，后置）、健康度监测、网络总开关 |
| **计价中心** | 各环节独立 token/费用计价 + 总计价，价格表基于 LiteLLM 数据库 |
| **插件总线** | 事件发布订阅（`chat:finished`、`node:learned` 等）、UI 插槽、SDK、权限系统 |

### 官方插件（随产品发布，可禁用）

| 插件 | 一句话 | 关键体验 |
|------|--------|---------|
| **知识树** 🌳 | 对话时，右侧实时长出你正在学的知识结构 | 每轮对话后自动提取知识点挂到树上；点击任意节点可"锚定"该节点继续追问；学习不再迷失 |
| **面包屑轨迹** 🍞 | 自动记录"你今天学会了什么"（Done-list） | 零手动输入；每天一句温柔的总结："今天你搞懂了闭包，还顺手理清了作用域链"；周/月回顾 |
| **遗忘地图** 🧠 | FSRS 算法预测每个知识点的记忆保留率 | 知识树节点按记忆强度渐变着色；输入考试日期→看到"考试当天预计遗忘图"；到期节点温柔浮现"要不要聊聊这个？" |
| **心晴** 🌤 | 从对话时间与语气觉察你的状态（默认关闭） | 深夜高频挫败提问→"这个问题不小，睡一觉再战它也许更划算"；从不评判，只陪伴 |
| **笔记精灵** 📝 | 对话自动沉淀为结构化笔记 | 挂在知识树节点下；可导出 Markdown（Obsidian 友好） |
| **轻计划** 🪶 | 低压力计划辅助 | 自然语言排计划；只提示"你上周说想看的 XX 还要安排吗"，不催办 |
| **真链接** 🔗 | 学习资源搜索，先访问验证再展示 | 每条推荐资源都是程序实测可访问的活链接，附内容摘要 |

### 插件生态（v1.0 方向）

- `./mods` 目录动态加载，热重载；`mod.json` 声明权限，安装时用户确认
- SDK：TypeScript 类型定义 + 事件钩子 + 命名空间化数据读写 + UI 插槽
- 三层开放度：JS 沙盒小工具 → SDK 深度业务插件 → WASM/Python-Sidecar 硬核插件
- 内置插件商店，支持给开发者募捐入口

## 版本路线

| 版本 | 内容 | 验证的假设 |
|------|------|-----------|
| **v0.1 MVP** | 对话 + 知识树实时生成 + 面包屑轨迹 + 计价中心 + API 设置 | "对话即数据"的核心体验是否成立、是否让人惊喜 |
| v0.2 | 遗忘地图（FSRS）+ 笔记精灵 | 记忆可视化是否带来复访动力 |

| v0.4 | 插件 SDK + 热重载 + 示例插件 + 商店雏形 | 开发者 10 分钟能否写出第一个插件 |

## 关键决策与理由（我替你做的判断，可推翻）

1. **桌面端优先（Tauri），移动端后置。** 学习主场景在电脑；Tauri 安装包小、内存省、天然支持插件架构。
2. **不做账号系统、不做云同步（v1.0 前）。** 本地优先是产品灵魂也是隐私承诺；同步未来可作为可选插件。
3. **心理监测默认关闭。** 这是产品里最需要分寸感的功能，宁可保守。
4. **知识树优先于遗忘预测进 MVP。** 知识树是"每次对话都能感受到"的即时价值；遗忘预测需要积累数据后才发光。
5. **不追求大而全的"私人秘书"。** 资料里有数字分身/全渠道秘书的方向，我判断那会稀释产品：Breadcrumb 只做学习这一件事，做到极致。
