## 一、总原则

**这个项目由 AI 全权实现，因此仓库本身就是给 AI 造的工厂。**
工厂的三根支柱：

1. **确定性护栏**——类型系统、测试、lint、commit 校验、CI。AI 撞到护栏会被自动弹回，错误日志自动喂回给 AI 修复。人不当保姆。
2. **规范驱动**——先写 spec 再写代码。每个功能从"点菜"（自然语言需求）到"出餐"（通过全部检查的代码）走固定流水线。
3. **自我记录**——commit / ADR / CHANGELOG / 进度文件，让任何一个新开的 AI 会话在 1 分钟内接管全局。

## 二、技术栈（已定，除非审核推翻）

| 层 | 选择 | 理由 |
|----|------|------|
| 应用壳 | **Tauri 2**（Rust） | 轻量（~10MB）、跨平台、原生支持插件/Sidecar 模式 |
| 前端 | **React + TypeScript (strict)** + Vite + Tailwind | AI 训练分布中最主流 = AI 出错率最低 |
| 状态编排 | **XState**（仅用于跨模块流程） + zustand（局部状态） | 顺序契约硬性锁死，防隐式依赖 bug |
| 数据 | **SQLite + Drizzle ORM**，schema 单文件 | 单文件数据库、强类型契约、AI 只能"照类型填空" |
| 校验 | **Zod**（一切外部输入/LLM 输出边界） | LLM 返回的 JSON 必须过 Zod 才能进入系统 |
| 遗忘算法 | **ts-fsrs** | Anki 同款 FSRS，业界最准的开源间隔重复调度 |
| LLM 接入 | 自研薄适配层（OpenAI 兼容格式），价格表参考 LiteLLM | 支持每环节独立配置 API；后接 Ollama |
| Monorepo | **pnpm workspaces** | 轻量物理隔离，官方插件各占一个 package |
| 测试 | Vitest + fast-check（属性测试）+ Playwright（后置） | 密集测试网 |
| 质量 | Biome（lint+format）+ commitlint + husky + lint-staged | 硬性拦截层 |
| CI | GitHub Actions：typecheck → lint → test → build | 红灯不许合 |

**明确不做的事**：不整仓融合任何现有开源项目（吸收算法库而非搬运仓库）；不上微服务/微前端；v1.0 前不做账号与云端。

## 四、AI 工厂：Claude Code 配置方案

> 你问"什么配置、什么 MCP、什么 skill 最适合"。我的判断：**Claude Code 本体已经是最强的工厂主体**
> （读写代码、跑终端、子代理、多智能体 workflow、code-review、计划模式、持久记忆都是原生能力）。
> 工厂的关键不在堆插件，而在仓库侧的护栏与流程。按需增补，拒绝预装一堆用不上的东西。

### 4.1 CLAUDE.md（AI 宪法，仓库建立当天写入）

包含四部分：
1. **AI 可读性编码规范**（资料 P1 七条：行为局部性 > 盲目 DRY、strict 类型禁 any、文件 ≤200 行、语义化全名命名、只用主流范式、每文件头部两句话摘要、变更后更新架构文档）
2. **防偷懒协议**（零占位符/零 TODO 蒙混、禁止删测试或硬编码返回值凑通过、完成前自检清单：测试过了吗/边界处理了吗/文档更新了吗）
3. **流程规范**（Conventional Commits、spec 先行、ADR 触发条件、遇困难 SOP）
4. **产品原则摘要**（五条产品原则，让每个技术决策都对得起产品灵魂）

### 4.2 钩子与硬护栏（harness 层面）

- husky pre-commit：lint-staged（Biome）+ commitlint —— AI 提交不合规直接被终端报错弹回
- Claude Code hooks：文件编辑后自动跑 `tsc --noEmit` 与相关测试，错误即时回灌
- CI：PR 必须全绿才能合入 main

### 4.3 技能（skills，放在仓库 .claude/skills/，随用随建）

初期建三个，之后按"遇到新工作流→沉淀为 skill"的规则自然生长：
- `add-feature`：点菜流水线 SOP（写 spec → 拆 tasks → 逐任务实现 → 验收 → 更新 CHANGELOG）
- `add-plugin`：新建官方插件的脚手架流程（目录、mod.json、SDK 对接、注册测试）
- `solve-hard-problem`：困难 SOP（提炼困难 → WebSearch/GitHub 搜开源方案 → 验证真实性与维护状态 → 以库形式引入 → 记 ADR）

### 4.4 MCP（初期一个都不装）

理由：Claude Code 自带 WebSearch/WebFetch（查资料、验证链接）、Bash（git/gh 一切操作）。
未来触发条件明确时再装（例如需要浏览器自动化测试 UI 时）。**需要时我会自己提出并说明理由。**

### 4.5 质量升级手段（按需启用）

- 重要功能合入前：`/code-review`（多智能体审查我自己的代码，你也可以随时说"ultracode"让我全程多智能体作业）
- LLM 相关功能：用 DeepSeek key 做 LLM-as-judge 评测与模拟用户测试数据（promptfoo/DeepEval 择一）
- 模块间接口稳定后：引入 Stryker 变异测试，防"假测试"
