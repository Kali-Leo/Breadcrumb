## 二、架构与工程点子（来自架构讨论）

| # | 点子 | 判断 |

| A3 | "融合十几个开源项目"的整仓融合思路 | ⚠️ **不采纳整仓融合**。Breadcrumb 是一个全新产品，不存在要硬融合的旧项目。正确姿势是"薄壳 + 精选算法库"（如直接依赖 ts-fsrs），保留了原思路里"隔离、剪枝、契约"的精髓，扔掉"搬运整个仓库"的包袱 |

| A6 | 插件三层开放度：JS 沙盒 / SDK 深度业务 / WASM+Sidecar（含 Python） | ✅ 采纳"默认层级二 + WASM 支撑高复杂度" |

| A9 | 契约测试 Pact / 变异测试 Stryker / 属性测试 fast-check | ✅ 均真实。fast-check 早期引入；Stryker/Pact 等模块间接口多起来后再上（避免初期过度工程） |
| A10 | 剪枝工具链 Knip / ast-grep / 覆盖率分析 | ✅ 真实，按需使用 |
